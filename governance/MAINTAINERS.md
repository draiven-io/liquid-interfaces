## Becoming a Maintainer

### Path to Maintainership

1. **Active Contribution**: Sustained, high-quality contributions over time
2. **Community Involvement**: Helping others, reviewing PRs, participating in discussions
3. **Technical Understanding**: Deep knowledge of the specifications
4. **Alignment**: Understanding and commitment to project values

### Nomination Process

1. Existing maintainers may nominate contributors
2. Nominees are discussed among current maintainers
3. Consensus is required for new maintainers
4. Invitation extended to nominee

### Expectations

Maintainers are expected to:

- Review pull requests in a timely manner
- Participate in project discussions
- Help guide the project direction
- Mentor new contributors
- Uphold the Code of Conduct
- Communicate proactively about availability

---

## Maintainer Responsibilities

### All Maintainers

- Review and merge pull requests
- Triage issues
- Participate in RFCs
- Support the community
- Represent the project professionally

### Core Maintainers

- Set project direction
- Make final decisions on RFCs
- Manage releases
- Handle Code of Conduct enforcement
- Oversee governance processes

### Specification Maintainers

- Own quality of specific specifications
- Guide specification evolution
- Review specification-related PRs
- Ensure consistency within their area

---

## Decision Making

### Consensus-Based

We strive for consensus in all decisions. Maintainers discuss and iterate until agreement is reached.

### Voting

When consensus cannot be reached:
- Core maintainers vote
- Simple majority wins
- Ties broken by lead maintainer

### Escalation

Community members may raise concerns about decisions through:
1. GitHub Discussions
2. Direct contact with maintainers
3. Code of Conduct channels if needed

---

## Stepping Down

Maintainers who wish to step down should:
1. Notify other maintainers in advance
2. Help transition responsibilities
3. Be recognized as emeritus if desired
